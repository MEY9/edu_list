# 收录与审核标准

## 范围

收集教学与学习、课件制作、仿真、编程教育、学习管理、评价和学校管理相关的 GitHub 项目。课程资源型项目可以收录，但必须说明其资源或平台属性。通用工具必须对应具体教学用途；仅因 Star 高而没有教育用途的框架不收录。

## 主清单

当前门槛为 Star ≥ 1,000，由 `data/categories.yml` 的 `policy.min_stars` 配置。条目需要 `status: accepted`，且最新有效元数据没有归档或禁用标记。分类内按 Star 降序排列。

初始接受条目由 Codex 辅助核对上游 README 和仓库资料，属于资料核对，不代表人工部署验收、教学效果验证或商业使用许可审查。维护者可继续提升审核深度、修改用途或移出条目。

教育关系：

| 值 | 含义 |
| --- | --- |
| `native` | 主要用途就是教学、学习或学校业务 |
| `adaptable` | 通用工具，可整合到教育产品；需写明教学用途与整合要求 |

## 状态与展示

| 人工状态／客观条件 | 展示位置 |
| --- | --- |
| `candidate` | 待审核页，Star 增加也不会自动收录 |
| `accepted` 且符合门槛 | 主清单 |
| `accepted` 但 Star 不足 | 观察清单 |
| `removed` 或已归档／禁用 | 归档与移出页 |
| `accepted` 但还没有有效元数据 | 待审核页 |

新增项目默认候选。候选、移出必须填写原因；迁移项目可填写 `replacement: owner/repo`。低 Star 的当前迁移仓库可保留在观察页，不借用旧仓库 Star 数。

超过 180 天未推送的项目提示维护状态需复核，不自动认定失效；成熟项目也可能很少提交。`pushed_at` 是推送时间，不等同于最后一条代码提交时间或最后一次维护活动。

## 核对深度

| 值 | 要求 |
| --- | --- |
| `readme_reviewed` | 阅读上游资料，说明功能与教育用途，保留来源 |
| `code_reviewed` | 在资料核对基础上检查相关实现，记录范围和局限 |
| `run_verified` | 实际运行并记录环境、步骤和结果，附验证依据 |

核对方式需如实写明是否使用工具辅助。日期是资料核对时间，Star 获取日期是另一个字段。通用 AI 工具标记为“可用于教育”，不能把可构建教学助手描述为已验证的教育产品。

## 许可与费用

API 自动识别的许可证标识单独展示。`NOASSERTION` 或缺失显示“需复核”；自定义许可、模型、字体、图片、课程、游戏关卡和数据集另查上游条款。公开源码不代表所有附属资产均可按相同方式使用。

费用只记录结构性成本：服务器、部署运维、API、模型推理与托管服务。不承诺第三方服务永久免费，也不维护未经核对的价格。

## 数据刷新

刷新只更新客观数据，不改人工状态、中文介绍或审核深度。网络或 API 故障时保留上次成功的数据与时间；不写入假的零 Star。部分失败会让工作流失败且不提交刷新结果，待后续重试。增长比较的是明确标注日期的前一期快照，不虚称固定 7 日增长。
